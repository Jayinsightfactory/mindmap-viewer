# Orbit 데이터분석 기능 설계 표준 (정밀분석 5원칙)

> 2026-08-13 확립. **모든 데이터분석 기반 기능은 이 표준을 충족해야 한다.**
> 근거 사례: 세밀분석(deep-dive, 앱→앱 워크플로우 트레이스) · 발주검증(orderflow, 거래처×차수 ①확인·②정리·③변경).
> 뿌리: CLAUDE.md "정밀 분석(통계 아님)" · 골모드("AI가 이 일을 직접 할 수 있나").

## 5원칙 (설계·리뷰 체크리스트)

1. **엔티티 단위 (집계 금지)**
   - 인물·거래처·업무·차수·품목 등 **구체 단위**로 분해. "nenova 155회 사용" 같은 총계 통계 금지.
   - 판정: 화면에 나오는 숫자가 "누가/무엇을/어느 건" 으로 드릴다운되는가?

2. **파이프라인·단계 추적 (흩어진 이벤트 금지)**
   - 낱개 이벤트 나열이 아니라 **소스→처리→산출의 실제 순서·앱→앱 흐름·핸드오프**로 복원.
   - 판정: "이 산출물이 어떤 데이터로, 어떤 순서로 만들어졌나"를 단계로 보여주는가?

3. **근거 첨부 (추적 가능)**
   - 모든 주장에 **원문/화면명/시각/입력값** 근거를 붙인다. 감사(audit) 가능해야.
   - 판정: 각 판정 옆에 클릭·확인 가능한 근거(카톡 원문·화면·ts)가 있는가?

4. **정직한 불확실성 (모르면 모른다고)**
   - 확인 못한 건 **blindSpots / WARN / 미확인**으로 명시. 추정은 '추정' 접두. **FAIL(반증)과 미확인(데이터없음) 구분**.
   - 판정: 데이터 공백을 PASS로 위장하지 않는가? 사각지대가 숫자로 보이는가?

5. **자동화 지향 (골모드)**
   - 최종 기준은 **"이걸로 AI가 이 일을 직접 할 수 있나"**. 통계·대시보드는 부산물.
   - 판정: 각 분석이 자동화 방법(nenovaweb기능/PAD/규칙)과 신뢰도(100%가능/검토1스텝/부적합)로 이어지는가?

## 구현 규약

- **산출**: `ops-report` kind=`<feature>:<entityId>` (+ 별칭 `<feature>`). 뷰어는 admin 탭(iframe 인라인).
- **무과금 우선**: 규칙기반 → 필요 시에만 LLM(owner PC CLI, `runClaude`, API키 불필요). 사용량 가드 준수.
- **자기개선 루프**: 이전 리포트의 추정·사각지대를 다음 회차에 데이터로 보강.
- **데이터 소스 정직**: 서버 LIMIT·미러링 누락·좌표-라벨 공백 등 **소스 한계를 blindSpots에 명시**(관측한계 ≠ 실제 없음).
